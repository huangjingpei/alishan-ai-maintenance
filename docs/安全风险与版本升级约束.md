# 安全风险与版本升级约束

审计日期：2026-08-27

## 当前审计结果

在锁定恢复版兼容依赖后执行：

```powershell
npm audit
npm audit --omit=dev
```

当前报告 3 个高危依赖项：

| 依赖 | 类型 | 说明 |
|---|---|---|
| `adm-zip` | 直接生产依赖 | `<0.6.0` 存在恶意 ZIP 触发超大内存分配的拒绝服务风险 |
| `electron` | 直接开发/运行时依赖 | Electron 24.8.8 已落入 npm 当前高危公告范围 |
| `extract-zip` | Electron 工具链的传递依赖 | 当前版本被审计工具标记为高危 |

## 为什么没有自动执行 npm audit fix --force

现有 `main.x64.jsc` 与 Electron 24.8.8 的 V8 字节码绑定。强制升级 Electron 很可能使 JSC 无法加载；强制升级压缩库也可能改变更新或扩展同步行为。

因此禁止新人直接执行：

```text
npm audit fix --force
```

## 短期措施

1. 所有开发和首次运行放在隔离环境；
2. 不加载不受信任的本地 ZIP 或更新包；
3. 对 ZIP 来源、大小、文件数、解压后总大小和路径穿越做限制；
4. 对 Electron 打开的远程页面保持最小权限，限制 Node 集成和 preload 暴露面；
5. 正式安装包必须代码签名；
6. 不使用真实客户数据做开发测试；
7. 每次发布重新执行依赖审计并归档结果。

## 中期修复计划

### adm-zip

建立专门分支升级到审计建议版本，先盘点所有 `adm-zip` 调用，再测试：

- 正常压缩包；
- 超大声明尺寸；
- 高压缩比压缩炸弹；
- 路径穿越；
- 损坏文件；
- 更新包或扩展包的签名、哈希和来源验证。

### Electron

Electron 不能在保留现有 JSC 的同时随意升级。应先按《JSC文件影响与进一步逆向方案》重建普通 JavaScript 主入口，移除 Bytenode 字节码依赖，再升级到公司选定并受支持的 Electron 版本。

升级必须同时验证：

- Chromium 页面行为；
- preload 和 contextIsolation；
- IPC；
- `better-sqlite3` ABI；
- BrowserWindow/BrowserView 行为；
- 自动化页面选择器；
- 安装、升级和用户数据兼容。

## 当前发布阻塞项

以下问题关闭前，测试包不得作为正式生产版本对外发布：

- `appId` 仍是占位值；
- 安装包未进行公司 Authenticode 签名；
- 使用默认 Electron 图标；
- 267 个文件与原 protection manifest 哈希不同，尚未完成运行时确认；
- Electron 24 与压缩依赖高危项尚未形成批准的缓解或升级计划；
- 尚未完成隔离环境功能、升级和安全回归。
