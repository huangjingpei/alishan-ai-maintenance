# 标识符可读性恢复工具链

本仓库的业务代码来自反混淆恢复：模块名、顶层函数名、字符串已恢复，但局部变量和内部函数仍是 `_0x4eaaf7` 这类十六进制名。本文说明如何用仓库自带的工具链把它们恢复为可读名字，以及每一步必须通过的验证门。

## 已确认的安全前提

- `protection-manifest.json` 的 SHA-256 清单**没有对 `.js` 快照的运行时强制校验**：反编译出的 `.js` 代码运行时代码零引用；`.jsc` 字节码字符串探测只发现 `integrity-failure` 等生命周期上报事件名，无 manifest 文件名、哈希算法相关内容（manifest 的哈希针对的是 `.jsc` 自身完整性，属字节码范畴，不在本文反混淆范围）。`scripts/integrity-report.mjs` 仅做差异报告。
- 运行入口 `dist-protected/main.js`（薄装载器）执行 `require(main.x64.jsc)`；`.jsc` 是 **bytenode 编译的自包含 V8 字节码**（约 385KB，内部不含对 `./main/*.js`/`./shared/*.js` 的 require，也不含 `radarAi`/`webhookMonitor` 等模块名，已用字节码字符串探测确认）。因此**磁盘上的 `./main/*.js`、`./shared/*.js` 仅是可阅读的反编译快照，运行时并不执行，改名仅供人读、不改变行为**；真正要改写运行行为（去服务器化、AI 改向本地 Ollama 等），只能在 `main.js` 装载器层植入 `Module._load`/axios 拦截钩子，在 `require(jscPath)` 之前截住 jsc 内部的请求。反混淆改名仍强制走本文验证门——等价校验能挡住重命名引入的遮蔽/引用漂移。
- main/shared/preload 已确认没有 `eval`、`with`、hex 标签、hex 字符串动态访问、hex 对象键；仅存在少量 `obj._0x...` 成员属性访问（改名不触碰）。

## 工具

| 脚本 | 作用 |
|---|---|
| `scripts/rename-hex.mjs` | AST 级作用域感知的 `_0x` 标识符重命名。来源分档：解构别名还原原名（`PLATFORM_SELECTORS: _0x300dc` → `platformSelectors`）、require 模块名、参数/局部按默认值与右侧形态推断、catch 统一 `error`。含三重碰撞检查（同作用域重名、祖先绑定截获、全局名捕获），冲突自动加数字后缀。 |
| `scripts/rename-fn-semantic.mjs` | 占位函数名（`fn`/`fnN`）语义化。`--from-exports` 从 `{ 导出名: fnN }` 对象字面量机械还原；`--map map.json` 应用人工/AI 整理的语义命名表。碰撞检查同上。 |
| `scripts/verify-ast-equiv.mjs` | AST 语义等价校验：把两棵 AST 的绑定标识符规范化为 b1/b2/... 后整体序列化对比。重命名引入的任何遮蔽、漏改、错改都会报 NOT EQUIVALENT。 |
| `scripts/golden-db-harness.mjs` | dbManager 运行时黄金基线：在临时目录执行固定的建库/迁移/CRUD 流程并序列化结果。需用 `ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe` 运行（better-sqlite3 按 Electron ABI 编译）。 |
| `scripts/run-readability.sh` | 批量驱动器：读「计数 路径」清单，逐文件执行 `rename-hex --write` → 残留校验 → `rename-fn-semantic --from-exports --write` → `git show HEAD` 基线 → `verify-ast-equiv`（须 EQUIVALENT）→ `validate` → 原子 `git commit`；单文件失败则 `git checkout` 回滚并记 SKIP，继续下一个。自动跳过 `renderer/assets` 与对象键/成员属性。 |

## 标准流程（每个文件都必须走完）

```bash
# 1. 保存改名前原文件（等价校验与黄金基线的参照）
git show HEAD:path/to/file.js > .temp/orig.js

# 2.（仅 dbManager 等数据库模块）改名前黄金基线
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe scripts/golden-db-harness.mjs .temp/golden/before.json

# 3. 试运行看重命名报告（residual.other 必须为 0）
node scripts/rename-hex.mjs path/to/file.js

# 4. 应用 + AST 等价校验（必须 EQUIVALENT）
node scripts/rename-hex.mjs path/to/file.js --write
node scripts/verify-ast-equiv.mjs .temp/orig.js path/to/file.js

# 5. 占位函数名语义化（可选，建议控制器类文件做）
node scripts/rename-fn-semantic.mjs path/to/file.js --from-exports --write
node scripts/rename-fn-semantic.mjs path/to/file.js --map <name-map.json> --write
node scripts/verify-ast-equiv.mjs .temp/orig.js path/to/file.js   # 再次等价校验

# 6. 仓库级门禁
npm run validate    # 267 个文件语法零失败
npm test            # 本地接口契约 6/6

# 7. 启动冒烟（首次大批量改动后必做）
node scripts/dev-local.mjs   # 日志应出现 [DB] SQLite 数据库已成功初始化 与 whenReadyDone

# 8.（数据库模块）改名后黄金基线必须与改名前逐字节一致
ELECTRON_RUN_AS_NODE=1 node_modules/electron/dist/electron.exe scripts/golden-db-harness.mjs .temp/golden/after.json
diff .temp/golden/before.json .temp/golden/after.json
```

注意：`dev:local` 的本地服务端口固定 48765，重复启动报 `EADDRINUSE` 时先 `netstat -ano | grep 48765` 清理残留进程。日志里 `localhost:5173 ERR_CONNECTION_REFUSED` 是 Vite 开发服务器不存在的预期回退，随后会加载恢复版 renderer，不是故障。

## 命名约定

- 占位名只在语义线索不足时使用：参数 `argN`/`options`、局部 `result`/`value`/`list`/`text`、函数 `fnN`。看到 `fnN` 说明该函数还没做语义化。
- 语义命名表（`--map`）由维护者阅读函数体后编写；名字应描述行为（`waitForSelfComment`、`clampSmallCount`），不确定时宁可保守。映射表建议存 `.temp/` 之外留档不强制——git diff 本身就是审计记录。
- 不要改：对象键、成员属性（含 `._0x...`）、字符串字面量、renderer/assets 下带哈希的 bundle、三个 `.jsc`。
