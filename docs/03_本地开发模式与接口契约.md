# 本地开发模式与接口契约

文档版本：1.0  
适用版本：2.9.89 恢复版  
最后更新：2026-08-27

## 1. 目标与边界

本地开发模式用于公司内部维护、接口迁移和自动化回归。它让未打包的 Electron 应用连接到本机服务，从而不依赖原产品服务器进行启动鉴权和接口联调。

它不是生产授权替代方案：

- 必须显式设置 `HUOKE_LOCAL_DEV=1`；
- 只允许 `electron .` 等未打包运行形态；
- 本地服务只监听 `127.0.0.1`；
- 开发用户数据固定隔离在 `.local-data`；
- `electron-builder` 的 `files` 未包含 `local-services`、`scripts` 和 `.local-data`；
- 打包程序继续使用原鉴权和密文运行配置。

## 2. 一条命令启动

```powershell
cd E:\zhibodou-ai\alishan-ai-maintenance
npm install
npm run dev:local
```

该命令会依次：

1. 执行静态校验；
2. 在 `127.0.0.1:48765` 启动本地服务；
3. 把 `API_BASE` 与 `API_BASE_2` 指向 `http://127.0.0.1:48765/api`；
4. 设置 `HUOKE_LOCAL_DEV=1`；
5. 以 `.local-data` 作为 Electron `userData`；
6. 启动未打包 Electron，退出应用时停止本地服务。

恢复版 JSC 在未打包状态下仍会尝试连接原前端开发服务器。该服务器源码已经遗失，因此 `main.js` 会在连接失败时自动回退到 `dist-protected/renderer/index.html`，并关闭自动打开的 DevTools。这个回退只在 `HUOKE_LOCAL_DEV=1` 且应用未打包时安装。

恢复版 JSC 还会优先读取地域解析缓存，而不是直接采用 `API_BASE`。本地引导会把隔离目录中的 `api_base_region_cache` 固定为 localhost，并由 `apiBaseRegion.js` 跳过公网 IP 地域探测。日志中的 `[ApiBase] 生效=` 必须显示 localhost；若仍显示原域名，说明启动的不是当前 `dev:local` 流程。

只调试服务端契约可运行：

```powershell
npm run local:server
```

端口冲突时：

```powershell
$env:HUOKE_LOCAL_PORT = '48766'
npm run dev:local
```

## 3. 文件职责

| 文件 | 职责 |
|---|---|
| `scripts/dev-local.mjs` | 编排本地服务与 Electron 进程，注入开发环境变量 |
| `scripts/local-backend.mjs` | 单独启动本地服务 |
| `local-services/backend.mjs` | localhost 路由与确定性响应 |
| `local-services/runtime-config.dev.json` | 本地兼容运行配置；集中维护页面选择器和文本模式 |
| `local-services/runtime-config-validation.mjs` | 与恢复版主进程一致的必填字段、数值和正则校验 |
| `tests/local-backend-contract.test.mjs` | 本地接口契约回归测试 |
| `dist-protected/main/runtimeConfig.js` | 仅在受控开发态接受 `data.plain` |
| `dist-protected/main.js` | 在加载 JSC 前切换隔离的 `userData` |

## 4. 当前本地接口行为

| 方法与路径 | HTTP | 行为 |
|---|---:|---|
| `GET /api/healthz` | 200 | 健康检查 |
| `POST /api/device/report` | 200 | 返回开发态 active 授权 |
| `POST /api/auth-codes/use` | 200 | 返回固定开发令牌 |
| `GET /api/radar/runtime-config` | 503/422/200 | 未启用时 503；字段不完整时 422；校验通过后返回明文配置 |
| `GET /api/product/check-update` | 200 | 固定无更新 |
| `POST /api/radar/report-data` | 200 | 接收但不保存 |
| `POST /api/feedback/submit` | 200 | 接收但不保存 |
| AI、额度、上传接口 | 501 | 明确标记未实现 |
| 未知接口 | 404 | 返回方法和路径用于补全清单 |

服务只记录方法和路径，不记录鉴权码、请求正文或用户数据。

## 5. 已实现响应契约

### 5.1 `POST /api/device/report`

```json
{
  "code": 200,
  "success": true,
  "localDevelopment": true,
  "data": {
    "status": "active",
    "isPaid": true,
    "isTrial": false,
    "token": "LOCAL-DEV-TOKEN",
    "planType": "local-development",
    "expireTime": null,
    "aiQuota": null,
    "personaTestQuota": null,
    "workPublishQuota": null
  }
}
```

`localDevelopment` 是审计标识；不要删除。额度使用 `null`，不伪造“无限额度”。

### 5.2 `POST /api/auth-codes/use`

```json
{
  "code": 200,
  "success": true,
  "localDevelopment": true,
  "token": "LOCAL-DEV-TOKEN",
  "planType": "local-development",
  "expireTime": null,
  "message": "本地开发模式已启用"
}
```

### 5.3 `GET /api/radar/runtime-config`

顶层 `configured` 未启用：

```json
{
  "code": 503,
  "success": false,
  "localDevelopment": true,
  "error": "LOCAL_RUNTIME_CONFIG_NOT_CONFIGURED",
  "msg": "请先填写 local-services/runtime-config.dev.json，并将 configured 改为 true"
}
```

`configured:true` 但仍有空字段、占位值、非法正则或非正数参数时返回：

```json
{
  "code": 422,
  "success": false,
  "localDevelopment": true,
  "error": "LOCAL_RUNTIME_CONFIG_INCOMPLETE",
  "msg": "本地运行配置未通过完整性校验",
  "details": ["commentV2.commentInput 不能为空"]
}
```

配置完成后的响应：

```json
{
  "code": 200,
  "success": true,
  "localDevelopment": true,
  "data": {
    "plain": {
      "version": "local-compat-2026-08-27.1",
      "commentV2": {},
      "dmV2": {},
      "gated": {},
      "videoEngageV2": {},
      "urls": {},
      "apiHooks": {},
      "selectors": {}
    },
    "etag": "local-compat-2026-08-27.1"
  }
}
```

示例中的空对象仅展示外层结构，不能直接使用。仓库默认的 `runtime-config.dev.json` 已提供一份根据恢复代码消费逻辑整理的兼容配置，并通过完整性校验；它不是抖音官方稳定接口，抖音页面改版后仍需更新并回归。

## 6. AI 接口未来实现时的建议响应

以下是假响应契约，用于开发和测试。上线前必须由业务负责人确认语义，并为每种响应增加测试。

### 6.1 线索匹配和视频匹配

安全的“不放行”样例：

```json
{
  "code": 200,
  "data": {
    "pass": false,
    "score": 0,
    "reason": "local rule: no matching rule",
    "main_post_comment": ""
  }
}
```

消费代码把缺失的 `pass` 当作通过，因此实现时必须显式返回布尔值。

### 6.2 评论决策

请求有多少条 `leads`，响应数组就应有多少项，并保持顺序：

```json
{
  "code": 200,
  "data": [
    {
      "should_like": false,
      "should_reply": false,
      "reply_content": "",
      "thought": "local rule: ignore"
    }
  ]
}
```

不要在未实现规则时默认 `should_like:true` 或 `should_reply:true`，否则会触发真实网页动作。

### 6.3 作品文案生成

```json
{
  "code": 200,
  "data": {
    "items": [
      {
        "title": "本地测试标题",
        "description": "本地测试描述"
      }
    ]
  },
  "workPublishQuota": null
}
```

### 6.4 作品额度

```json
{
  "code": 200,
  "data": {
    "remaining": null,
    "planType": "local-development"
  }
}
```

具体额度字段的 UI 消费尚未完全确认；在新增实现前，应先用 IPC 调用和 UI 回归确认字段名。

### 6.5 通用分析

`/radar/analyze` 的 `data` 结构由调用场景决定，当前只能确认客户端要求 `code === 200`。在响应结构未从真实业务需求确定前，继续返回 501，不要返回空的 200。

## 7. “运行环境未就绪”的定位与维护

该提示不是授权失败。它表示 `/device/report` 已成功，但 `/radar/runtime-config` 没有得到一份通过完整性校验的配置。

本次故障的直接原因是：顶层 `configured` 被改成了 `true`，但 `commentV2`、`dmV2` 和 `gated` 的必填字段仍是空字符串/空数组。本地服务曾错误地返回 200，主进程二次校验后仍判定 `ready:false`。现在本地服务会提前返回 422 和具体字段清单，不再产生这种“接口成功、应用不就绪”的歧义。

排查顺序：

1. 启动日志中的 `[ApiBase] 生效=` 必须是 `http://127.0.0.1:<端口>/api`。
2. 必须看到 `[LocalBackend] POST /device/report`。
3. 必须看到 `[LocalBackend] GET /radar/runtime-config`。
4. 随后应看到 `[RuntimeConfig] 已拉取本地开发明文配置 version=local-compat-...`。
5. 若出现 HTTP 422，直接检查响应 `details`；若出现 503，检查顶层 `configured`；若根本没有请求，说明没有从 `npm run dev:local` 启动或 API 基址未切换。

维护页面配置时：

1. 在公司批准的测试账号和隔离环境中打开当前抖音页面。
2. 逐一确认 `runtime-config.dev.json` 的 CSS 选择器、文本模式和超时值。
3. 不使用 `#__fake__`、`body` 等“能命中但语义错误”的占位值。
4. 每个选择器至少验证：目标存在、唯一性合理、错误页面不误命中。
5. 修改后把 `version` 改成可追踪值，例如 `local-compat-2026-09-02.1`。
6. 运行 `npm test`，再用测试账号执行只读/低风险场景。

`runtimeConfig.js` 仍会执行原完整性校验；缺少任何必填字段都会保持 `ready:false`。`runtime-config-validation.mjs` 在 HTTP 响应前执行同等约束，以便尽早给出可读错误。这两层保护都不应绕过。

## 8. 新增本地接口实现

修改 `local-services/backend.mjs` 时遵守以下顺序：

1. 先从调用方确认请求与响应字段；
2. 把响应样例补到本文；
3. 默认使用无动作或失败关闭语义；
4. 在 `tests/local-backend-contract.test.mjs` 添加成功、失败和边界用例；
5. 再实现路由；
6. 运行完整验证。

如果接入公司自有模型，密钥只能来自本机环境变量或公司秘密管理系统，不能写进仓库、运行配置或安装包。

## 10. 正式发布检查

- 不以 `npm run dev:local` 作为生产启动方式；
- 发布环境不得设置 `HUOKE_LOCAL_DEV`、`API_BASE=http://127.0.0.1...`；
- 安装包内不应出现 `local-services`、`tests`、`.local-data`；
- 恢复并验证公司正式授权服务或经审批的新鉴权系统；
- 更新服务必须校验 HTTPS、版本和代码签名；
- 对会产生点赞、评论、私信、发布等外部动作的接口进行人工审批和测试账号回归。
