# 去服务器化副作用与纠错结论

文档版本：2.0  
最后更新：2026-08-27

## 结论

当前仓库采用“显式本地开发模式”，不再采用 WorkBuddy 的全局 Hook 方案：

- 开发态鉴权由 `127.0.0.1` 本地服务返回，并带 `localDevelopment: true` 标识；
- 打包程序保持原鉴权与密文运行配置流程，不会静默跳过授权；
- 本地数据写入仓库 `.local-data`，与已经安装的软件用户数据隔离；
- 未实现的 AI 接口返回 HTTP 501，不伪装成成功；
- 本地兼容运行配置已补齐并通过完整性校验；未启用时返回 503，字段残缺时返回 422 和字段清单；
- 抖音网页仍是外部依赖，不能通过本地服务消除。

## WorkBuddy 方案的问题及处理

| 原改动 | 风险 | 当前处理 |
|---|---|---|
| 覆盖全局 `crypto.createDecipheriv` | 所有 AES-256-GCM 调用都可能收到伪造明文 | 已删除；生产仍执行真实 AES-GCM 解密 |
| 覆盖 `Module._load` 和 Axios 原型 | 请求边界不可审计，第三方请求也可能被误拦截 | 已删除；使用独立 localhost HTTP 服务 |
| 启动时写入高配额 pro 授权 | 污染真实用户配置，授权状态不可追踪 | 已删除；开发数据只进 `.local-data` |
| 选择器统一设为 `#__fake__` | 校验通过但功能必然超时，形成静默失败 | 已删除；配置未完成时 fail-closed |
| 所有 readiness 函数直接返回 true | UI 显示可用，执行层实际不可用 | 已恢复原校验 |
| 隐藏 renderer 的配置未就绪提示 | 丢失关键故障信号 | 已恢复原提示 |

## 副作用分级

| 能力 | 本地开发现状 | 后续工作 |
|---|---|---|
| 启动鉴权、激活 IPC | 可用；固定开发令牌 | 仅用于开发，不作为生产授权方案 |
| 运行配置 | 默认启用代码推导的本地兼容配置 | 根据抖音页面改版持续回归并维护选择器；只在测试账号验证外部动作 |
| AI 分析、评论决策、线索匹配 | 明确报 501 | 接入公司自有模型或本地规则引擎 |
| 数据上报 | 本地接收但不持久化 | 如业务需要，接入本地 SQLite/日志管道 |
| 文字反馈 | 本地接收但不持久化 | 如需闭环，增加本地存储和导出 |
| 反馈图片上传 | 明确报 501 | 设计文件大小、类型、清理周期后再实现 |
| 自动更新 | 固定返回无更新 | 正式发布前接入公司更新源和签名校验 |
| 抖音页面自动化 | 仍依赖在线页面 | 持续维护选择器与合规回归测试 |

## 不应再次采用的做法

1. 不要在入口文件中修改 Node/Electron 的全局加密函数或模块加载器。
2. 不要用非空假选择器骗过完整性检查。
3. 不要让未实现的 AI 服务返回“成功 + 空数据”；调用方可能把缺失字段解释为放行。
4. 不要把本地开发令牌、开发配额或明文运行配置用于安装包。
5. 不要直接编辑三个 `.jsc` 文件；当前本地适配点位于可读 JavaScript 层。

启动方法、接口响应和扩展步骤见《03_本地开发模式与接口契约.md》。
